# AI 資料整理術：免手工整理表格、網頁與會議逐字稿

## 用 AI 處理複雜的表格資料

## 1-1 情境導入

原教材的情境是一份「三個月銷售紀錄」Excel。每天一列，欄位包括：

- 編號
- 銷售日期
- 商品名稱
- 單次銷售數量
- 單價
- 入帳金額

傳統做法可能要使用篩選、樞紐分析、SUMIFS 或 Excel 函數；本單元先用 Gemini 快速整理，再把結果貼回 Excel 或匯出到 Google Sheets。

### 教師講稿

「AI 的價值不是代替我們理解數據，而是先做第一輪彙整。請注意：『賣最多』可能指數量最多，也可能指營收最高。如果提示詞沒有把指標講清楚，AI 即使算對，也可能答錯我們真正想問的問題。」

## 1-2 示範資料與原教材結果

原教材示範得到的月銷售額：

| 月份    | 總銷售額（元） |
| ------- | -------------: |
| 2025-01 |        190,260 |
| 2025-02 |        194,570 |
| 2025-03 |        161,930 |

商品彙整結果：

| 排名（依銷售數量） | 商品名稱 | 總銷售數量 | 總銷售金額（元） |
| -----------------: | -------- | ---------: | ---------------: |
|                  1 | 藍牙耳機 |         69 |          130,410 |
|                  2 | 智慧手環 |         63 |           81,270 |
|                  3 | 行動電源 |         62 |           61,380 |
|                  4 | 電競滑鼠 |         58 |           92,220 |
|                  5 | 機械鍵盤 |         52 |          181,480 |

### 關鍵洞察

- 銷售數量最高的是「藍牙耳機」。
- 銷售金額最高的是「機械鍵盤」。
- 「賣最好」若未定義，會產生兩種合理答案。
- 2025 年 2 月為三個月中總銷售額最高的月份。

## 1-3 操作示範

1. 開啟 Gemini。
2. 將 Excel 檔拖曳至對話框。
3. 輸入分析需求；長提示詞可用 `Shift + Enter` 換行。
4. 檢查 AI 回傳的月統計、商品統計與排序。
5. 使用結果旁的複製功能貼回 Excel，或匯出至 Google Sheets。
6. 抽查至少一個月份與一項商品的計算。

> 原教材提醒：Gemini 與 Google Sheets 整合方便；若無法直接下載 Excel，可複製表格或匯出到 Sheets 後再下載。

## 1-4 可直接複製的提示詞

### 基礎版

```text
你是一位資料分析助理。請僅根據我上傳的銷售明細檔進行分析：

1. 統計每個月份的總銷售額。
2. 統計每項商品的總銷售數量與總銷售金額。
3. 分別指出「銷售數量最高」及「銷售金額最高」的商品。
4. 製作 Markdown 表格，金額加上千分位。
5. 說明你的分組欄位與計算方式。
6. 若資料有空白、重複列或格式異常，請先列出，不要自行猜測或補值。
```

### 進階洞察版

```text
請只使用我上傳的銷售資料，先做資料品質檢查，再完成：

- 依月份彙總銷售額，計算月增減金額與月增減率。
- 依商品彙總數量、金額、平均單價。
- 各做一份「依數量排名」與「依金額排名」。
- 找出數量排名和金額排名差異最大的商品，說明可能原因。
- 最後提出 3 個可以由資料支持的營運觀察。

所有觀察都要附對應數字；資料未提供的原因不可寫成事實。
```

## 1-5 課堂提問

1. 「銷售量第一」是否等於「營收第一」？
2. 如果有退貨或折扣，現有欄位足以判斷真正獲利嗎？
3. 為什麼 AI 回傳表格後仍要抽查？

### 參考答案

1. 不一定。示例中藍牙耳機數量最高，但機械鍵盤金額最高。
2. 不足。至少還要折扣、退貨、成本、稅額等欄位。
3. 可能有日期解析、重複列、空值、欄位誤認或加總錯誤。

## 1-6 實作題

請學員改寫提示詞，找出：

- 哪個月銷售額最低？
- 各商品平均每筆銷售數量。
- 如果以「營收」規劃促銷，優先關注哪個商品？如果以「出貨量」規劃呢？

# 單元 2　請 AI 從複雜 PDF 抓數據、彙整成表格

## 2-1 情境導入

資料常分散在多份 PDF 的不同頁面與表格中。原教材以台北市道路交通事故統計為例，將三份不同年度的 PDF 匯入 NotebookLM，請 AI 單獨抓出台北市資料並製成表格。

### 為什麼使用 NotebookLM？

- 回答可限定於匯入來源。
- 適合跨多份文件比較。
- 可追溯引用來源，較方便人工核查。
- 比一般聊天機器人更不容易混入未提供的外部資料，但仍非絕對正確。

## 2-2 操作示範

1. 進入 NotebookLM。
2. 建立新筆記本。
3. 在「新增來源」選擇上傳檔案。
4. 上傳三份 PDF（原教材示例為 Y32.pdf、Y34.pdf、Y47.pdf）。
5. 等系統完成來源摘要；此摘要不是本次主要任務，可先略過。
6. 在對話框貼上提示詞並送出。
7. 檢查表格內每個數字的引用標記。
8. 將結果儲存為記事，方便後續使用。

## 2-3 原教材示範提示詞

```text
將三筆來源中，台北市的資料單獨抓出並做成表格。
```

這句能工作，但規格不夠明確。正式工作建議改成：

```text
你是一位政府統計資料整理員。請僅使用這三份 PDF，分別抓出「台北市」資料，
不要混入新北市或全國統計。

請按年度製作表格，欄位包含：
1. 肇事件數
2. 死亡人數
3. 受傷人數
4. 主要肇事原因及件數
5. 資料來源檔名與頁碼

規則：
- 保留原始單位與定義。
- 若不同年度定義不同，請不要硬合併，另加「口徑差異」說明。
- 找不到的欄位填「來源未提供」，不可自行推估。
- 表格後列出 3 點趨勢，但每點必須附數據依據。
```

## 2-4 原教材 2024 年示例

NotebookLM 將台北市 2024 年資料整理為表格，畫面中的主要數字包括：

| 項目                           |  統計數據 |
| ------------------------------ | --------: |
| 肇事件數                       | 21,876 件 |
| 死亡人數                       |    119 人 |
| 受傷人數                       | 29,079 人 |
| 肇事原因：汽（機）車駕駛人過失 | 21,520 件 |
| 肇事原因：行人（或乘客）過失   |    246 件 |
| 肇事原因：機件故障             |     26 件 |
| 肇事原因：其他                 |     84 件 |

> 教學重點：以上數字是「示範 AI 抽取後的結果」，正式使用時必須回到 PDF 的引用頁面逐項核對，也要確認「死亡人數」與「受傷人數」的統計口徑。

## 2-5 驗證方法

請學員做「三點核對」：

1. **欄位核對**：AI 是否把人數、件數、百分比混在一起？
2. **地區核對**：是否真的只取台北市？
3. **年度核對**：不同年度是否使用相同定義？

## 2-6 課堂練習

請把提示詞改成「比較三年趨勢」，並要求：

- 計算肇事件數增減率。
- 標出死亡人數最高的年度。
- 若統計口徑不同，停止計算增減率並說明原因。

### 參考提示詞

```text
請比較三份來源中的台北市道路交通事故資料。先檢查三年的統計定義與單位是否一致；
只有一致時才計算年增減率。請輸出年度比較表、兩點趨勢與一段資料限制說明。
每個數字都要附來源引用；不確定時明確標示，不要推估。
```

# 單元 3　全自動抓網頁資料並即時找出洞見

## 3-1 情境導入

原教材以網路書店暢銷榜為例：把多個來源網址貼入 NotebookLM，請 AI 比較榜單、找閱讀趨勢或整理排名。

> 必須先確認網站使用條款。NotebookLM 能讀到的通常是頁面可見文字，不代表能完整擷取動態內容、付費牆、登入後頁面或所有排名。

## 3-2 操作示範

1. 新建 NotebookLM 筆記本。
2. 選擇「網站」來源。
3. 貼入書店暢銷榜網址；多個網址通常以空格或換行分隔。
4. 插入來源並等候處理完成。
5. 查看 AI 自動摘要，但不要把摘要當作唯一答案。
6. 發問做比較、排序或趨勢分析。

## 3-3 原教材示例：多家書店暢銷榜

原教材將博客來、PChome 24h 購物與誠品線上的中文書榜單網址加入來源。畫面示例中可辨識的熱門作品包括：

- 《世界上最透明的故事 2》（杉井光）
- 《國寶（上下套書）》（吉田修一）
- 《擁有過，就好：告別青春的最後一封情書》
- 《她的名字是一條魚也是一隻鳥》
- 《被討厭的勇氣》
- 《臺灣漫遊錄》
- 《明亮燦爛的你》
- 《深夜食堂 30》

AI 的示例觀察指出：

- 《世界上最透明的故事》系列在不同榜單皆有高能見度。
- 吉田修一的《國寶》及部分青春／情感類作品表現強。
- 某來源只成功擷取前 8 名，因此第 9、10 名不能硬補。

## 3-4 可直接複製的提示詞

### 趨勢分析

```text
請只根據已加入的三個中文書暢銷榜來源，分析目前閱讀趨勢。

請輸出：
1. 各榜單前 10 名（書名、作者、名次、來源）。
2. 跨榜重複出現的書籍，依出現次數排序。
3. 可由榜單支持的 3 項閱讀趨勢。
4. 各來源的資料缺漏或擷取限制。

書名請做最小幅度標準化，但套書、續集、限定版不得擅自視為同一本。
找不到第 9、10 名時填「來源未擷取」，不可臆測。
```

### 原教材的表格任務

```text
把誠品和博客來前十名的書製作成表格。
```

建議改良為：

```text
請將博客來與誠品線上的榜單並排比較。每列為排名 1～10，
欄位為「排名、博客來書名／作者、誠品書名／作者」。
請移除網頁中的 <br> 等標記。資料缺漏要寫「來源未提供」。
表格後另列：
- 兩榜皆出現的作品
- 系列作與不同版本的判定說明
- 資料擷取時間與限制
```

## 3-5 教師講稿：相關不等於因果

「榜單可以告訴我們哪些書目前受到注意，但不能直接證明讀者為什麼購買。AI 可以提出『可能原因』，但必須清楚標成假設。例如影視改編、社群討論或促銷都可能影響名次，若來源沒有證據，就不能寫成已證實的原因。」

## 3-6 課堂題目

1. 同一本書有「一般版、套書、限定版」，應合併嗎？
2. 一個網站只有前 8 名，AI 應如何處理？
3. 排名資料可否直接推論整體閱讀人口偏好？

### 參考答案

1. 預設不要合併；先保留原項目，再視分析目的建立「系列」欄位。
2. 明確標示缺值與來源限制，不得補造第 9、10 名。
3. 不宜。榜單受平台客群、時間區間、促銷與計算方式影響。

# 單元 4　會議、訪談語音檔轉成逐字稿

## 4-1 情境導入

會議記錄耗時，人工邊聽邊記也容易漏掉內容。原教材示範三條路徑：

1. **NotebookLM**：上傳錄音，產生可供問答與整理的文字內容。
2. **Gemini**：直接上傳音檔並要求整理逐字稿。
3. **EchoScript AI**：強調時間戳、說話者分離、語言偵測、語調判斷與英文翻譯。

## 4-2 路徑 A：NotebookLM

1. 建立筆記本並上傳會議錄音。
2. 選取該音檔來源。
3. 提示 AI 產生完整逐字稿，而非摘要。
4. 若需要，要求標示「發話者 A／B」。
5. 複製結果到記事本或儲存為記事。

### 提示詞

```text
請只根據這份會議錄音製作逐字稿，不要摘要或改寫。

要求：
- 依發言順序分段。
- 能辨識時標示「發言者 A、發言者 B」；無法確定時標「發言者不明」。
- 保留專有名詞、數字、日期與決策語句。
- 聽不清楚處標示 [聽不清楚 00:00]，不要猜測。
- 每 30 秒或每次換人時加入時間戳。
```

> 原教材觀察：NotebookLM 可能會替逐字稿做少量潤飾，更適合理解內容，不一定是「原汁原味」的法務級逐字稿。

## 4-3 路徑 B：Gemini

將錄音檔上傳 Gemini，提示：

```text
請把這份錄音轉成逐字稿並標示發話者。先忠實轉錄，再於文末列出：
1. 決策事項
2. 待辦事項（負責人、期限）
3. 尚未解決的問題
無法從錄音確認的負責人或期限請填「未指定」。
```

原教材的行銷會議案例內容包括：

- 主持人詢問整體行銷計畫。
- 行銷主管提出期間限定商品或特別設計禮盒。
- 透過定期電子郵件與簡訊推送新品。
- 運用社交媒體與網紅合作，辦線上抽獎活動。
- 引導顧客分享內容，增加品牌曝光。

### 將示例整理成會議紀錄

| 類型     | 內容                   |
| -------- | ---------------------- |
| 會議主題 | 節慶行銷計畫           |
| 核心方案 | 限定商品／禮盒         |
| 推廣管道 | Email、簡訊、社群媒體  |
| 合作方式 | 網紅合作               |
| 活動機制 | 線上抽獎、顧客分享     |
| 預期目的 | 吸引關注、提升品牌曝光 |

## 4-4 路徑 C：EchoScript AI

原教材提供的連結為：

`https://aistudio.google.com/apps/bundled/echoscript`

操作概念：

1. 開啟網站並允許麥克風權限。
2. 可選擇直接錄音，或上傳 mp3、wav、m4a 等錄音檔。
3. 點擊產生逐字稿。
4. 系統分析音訊並區分 Speaker 0、Speaker 1 等發話者。
5. 檢查說話時間、語言、語調、逐字稿與英文翻譯。

原教材以約 60 分鐘錄音為例，處理約需 5 分鐘；此為當時示例，不是固定效能保證。

### EchoScript 畫面特色

- 顯示說話者。
- 顯示時間區間。
- 偵測語言。
- 判斷 Happy／Neutral 等語調。
- 提供英文翻譯。
- 原教材指出其傾向保留較口語、較接近原始發言的內容。

### 教師提醒

- 語調辨識是模型推測，不能當成員工情緒、態度或績效的客觀證據。
- 說話者標籤只是分群，不會自動知道真實姓名。
- 法務、醫療、研究訪談等高風險情境必須人工逐段校對。
- 若工具沒有一鍵匯出，可選取結果複製到文字編輯器，再交給 AI 做第二階段整理。

## 4-5 課堂練習

播放一段 2 分鐘雙人對話，請學員比較：

- 忠實逐字稿
- 潤飾版逐字稿
- 會議摘要

請回答：「三種輸出的用途有何不同？」

### 參考答案

- 忠實逐字稿：保留原始說法，適合稽核、研究或精確引用。
- 潤飾版：去除贅詞並提升閱讀性，適合內部傳閱。
- 會議摘要：只保留結論與行動，適合快速掌握，但不能取代原始紀錄。

# 單元 5　逐字稿太亂？交給 AI 摘要整理

## 5-1 情境導入

漫長會議常有偏題、插話、贅詞與語音辨識錯誤。原教材展示一份由 EchoScript 產生、看起來不太能直接使用的技術討論逐字稿，再交給 NotebookLM 做最後整理。

逐字稿主題涵蓋：

- 神經網路資料預處理
- 把英文單字轉成一連串數字
- 正面評價與負面評價的標記
- 從高頻字詞中篩選
- 程式碼不同方法執行結果不一致的疑問
- 字典還原與資料結構轉換

## 5-2 操作示範

1. 將完整逐字稿貼入 NotebookLM 或上傳成文字檔。
2. 在對話中明確要求「整理」，不要只說「摘要」。
3. 指定要保留的結構：說話者、主題、重點、疑問、待辦。
4. 要求保留原始引文或時間戳，以便追溯。
5. 檢查 AI 是否把不同人的話錯誤合併。

## 5-3 可直接複製的提示詞

### 結構化整理版

```text
你是一位技術會議紀錄員。請僅根據這份逐字稿整理內容，
不要加入外部知識，也不要替發言者補上未說過的結論。

請依「發言者」分組，每位發言者包含：
- 討論主題
- 核心觀點
- 使用的方法或流程
- 提出的疑問
- 待確認事項

最後再整理：
1. 全體共識
2. 尚未解決的分歧
3. 待辦事項（負責人／期限；未提及則寫未指定）
4. 可能的語音辨識錯字

每一項後面保留對應時間戳或一小段原句，方便人工核對。
```

### 保留原貌版

```text
請整理這份逐字稿，但保留原始逐字稿內容。
輸出分成兩區：
A. 原始逐字稿：只修正明顯標點，不刪除內容。
B. 結構化摘要：按發言者與主題整理重點。
任何你推測的修正都要用〔可能是：___〕標示，不得直接覆蓋原文。
```

## 5-4 原教材整理結果的結構

AI 將內容依發言者整理，例如：

### 參加者 1：資料特徵與預處理流程

- 資料轉換與評價：將英文單字轉為數字序列，並用 `1`／`0` 表示正面與負面評價。
- 資料集與篩選：說明目前使用一萬筆資料，並從高頻字詞中篩選。
- 預處理狀態：指出分析前必須先處理資料，因此畫面不會是原始文字。
- 疑義提出：詢問程式碼兩種方法執行結果不一致的原因。

### 參加者 2：資料結構與轉換必要性

- 字典還原：說明樣本中的數字對應到字典單字，可藉字典還原文字。
- 結構轉換：討論資料需要轉換成模型能處理的形式。

### 教師講稿

「這個案例最重要的不是 AI 把文字變漂亮，而是它建立了可追蹤的結構：誰說了什麼、用了什麼方法、哪裡有疑問。好的摘要不只是縮短，而是讓讀者快速找到決策、分歧與下一步。」

# 四、常見失敗與修正提示詞

## 失敗 1：AI 混入外部資料

```text
請重做。只能使用我上傳／加入的來源；若來源沒有答案，請寫「來源未提供」，
不要使用常識、搜尋結果或推測補足。
```

## 失敗 2：表格欄位不一致

```text
請先列出所有來源的原始欄位名稱、單位與定義，再建立對照表。
無法一一對應的欄位不要強行合併，請標示「口徑不同」。
```

## 失敗 3：漏掉缺值

```text
請重新檢查資料完整性。任何空白、未擷取、格式錯誤或無法判讀的值，
都必須保留一列並標記原因，不得刪除或補造。
```

## 失敗 4：摘要過度潤飾

```text
請降低改寫程度。保留原句順序、語氣、數字與專有名詞；
只補標點與分段。你不確定的修正請以方括號標出。
```

## 失敗 5：說話者分錯

```text
請不要猜姓名。改以「發言者 A／B／不明」標記；
只有聲音明確切換時才分段，重疊發言標記為 [多人同時說話]。
```

# 六、課末快問快答

1. **NotebookLM 和 Gemini 最大的使用差異是什麼？**  
   參考答案：NotebookLM 特別適合針對指定來源整理與引用；Gemini 適合快速處理檔案、分析與延伸任務。

2. **AI 給出表格後，第一個要檢查的是什麼？**  
   參考答案：資料來源、欄位定義、單位及缺值，而不是先看結論漂不漂亮。

3. **為什麼要在提示詞寫「不要自行補值」？**  
   參考答案：避免 AI 將推測包裝成資料，破壞可追溯性。

4. **「原汁原味逐字稿」與「會議摘要」能互相取代嗎？**  
   參考答案：不能。前者保存證據與語境，後者方便快速理解。

5. **網站前 10 名只抓到 8 名時怎麼辦？**  
   參考答案：標示來源只擷取 8 名，不可生成第 9、10 名。

6. **語調標記為 Happy，就能斷定發言者很開心嗎？**  
   參考答案：不能，這只是模型推測。
